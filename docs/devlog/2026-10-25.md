# 2026-10-25 PDF Organizer Development Log

## Work Summary

J님은 Men·Kids를 속성으로 등록했지만, 기존 포함 필터로는 두 속성이 모두 없는 도안을 찾을 수 없다고 설명했다. 속성 데이터를 유지하면서 기존 포함 조건과 조합할 수 있는 제외 필터를 추가했다.

## Work Completed

- Pattern Library에 `Exclude attributes (match any)` 체크박스 영역을 추가했다. 선택한 속성 중 하나라도 있는 도안을 제외한다. Men·Kids를 함께 선택하면 둘 다 없는 도안만 남으며, 속성 미지정 도안도 포함한다.
- 제외 조건을 갤러리 결과 캐시에 반영하고, 기존 포함·카테고리·검색·디자이너·즐겨찾기 조건과 교집합으로 적용했다. Any·None에서도 제외 조건은 유지한다.
- 포함·제외 양쪽에 같은 속성이 선택되면 마지막 선택이 우선하도록 반대쪽 선택을 해제한다. 조건 변경 시 페이지와 일괄 선택을 초기화하고 Clear filters로 제외 조건도 지운다.
- 속성 이름을 바꾸면 안정적인 ID로 선택 상태를 유지한다. 속성을 삭제하면 기존 대체·비우기 규칙을 제외 조건에도 적용하고 중복이나 포함 조건과의 충돌을 정리한다.
- 기존 체크박스 스타일을 재사용해 14px 이상의 글자와 줄바꿈을 유지했다. 정적 자산 버전을 갱신했다. 필터 추가를 위해 JSON 구조나 실제 도안의 분류를 변경하지 않는다.

## Decisions

- Men·Kids를 특별 취급하지 않고 등록된 모든 속성에 동일한 제외 기능을 제공한다. 속성 이름이나 폴더 구조를 새로 정의하지 않고, 기존 ID를 사용하는 일시적인 조회 조건으로 구현했다.
- 포함 조건은 선택한 속성을 모두 요구하고, 제외 조건은 선택한 속성 중 하나라도 있으면 숨긴다. 따라서 texture 포함 + Men·Kids 제외를 동시에 사용할 수 있다.
- 속성이 없는 도안을 제외 대상이라고 추정하지 않는다. 분류되지 않은 도안도 결과에 포함된다는 데이터 의미를 유지한다. 제외 조건은 기존 포함 필터와 마찬가지로 앱 새로고침 시 초기화된다.

## Current Status

- 전체 Node 테스트 57개와 변경 JavaScript 문법 검사가 통과했다. 새 단위 테스트는 Men 또는 Kids 한쪽만 있어도 제외, 속성 미지정·이전 데이터 포함, 다른 필터와 조합, Any·None, 이름 변경과 조회 중 데이터 불변을 검증한다.
- Chrome 전용 통합 검증에서 임시 샘플 130개 중 Men·Kids 제외 결과 65개, texture 포함까지 적용한 결과 22개를 확인했다. 조건 충돌 해소·검색/카테고리/디자이너/즐겨찾기 조합·페이지와 선택 초기화·전체 해제·속성 이름 변경/삭제 대체/비우기·재연결을 검증했다.
- 기존 Chrome 속성 저장·일괄 수정 및 속성 관리 통합 검증도 통과했다. 예기치 않은 브라우저 오류는 없었다. 2048·1280px, Chrome 100% 줌에서 화면과 14px 이상 체크박스 글자, 잘림·가로 넘침을 확인했다.
- 새 통합 테스트에서 초기 숨김 화면의 접근성 선택자와 비동기 재연결 완료 대기를 보완했다. 현재 세션에 Browser 스킬/제어 도구가 노출되지 않아 기존 Playwright와 격리된 Chrome·임시 OPFS 샘플을 사용했다. 실제 사용자 라이브러리는 변경하지 않았다.
- 로컬 수정 완료 상태이며 이전 디자이너 폴더 드롭다운 작업도 보존했다. 커밋·푸시·배포는 수행하지 않았다.

## Next Steps

- 앱을 새로고침한 뒤 제외 영역에서 Men과 Kids를 선택하여 사용한다.
- Men·Kids 표기가 아직 없는 도안은 결과에 남으므로, 필요한 도안에 실제 속성을 지정하며 분류를 보완한다.
