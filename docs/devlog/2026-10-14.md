# 2026-10-14 PDF Organizer Development Log

## Work Summary

J님의 PDF Organizer 2.0 계획 중 첫 단계와 흑백 스타일 변경을 구현했다. 기존 대량 정리에서 브라우저 종료 시 검토 입력이 사라질 수 있었으므로, 라이브러리 확장에 앞서 검토 자동 저장·복구와 중복 검사 부담 완화를 우선했다.

## Work Completed

- IndexedDB에 폴더 핸들, 파일 크기·수정 시각, 디자이너 선택, 수동 수정 파일명, 제외 여부, 저장 위치와 수동 입력 플래그를 저장한다. PDF 내용 자체는 저장하지 않는다.
- 입력 후 250ms 지연 저장, 저장 상태·실패·재시도 표시, 주요 작업 전 저장, 재접속 시 ‘이어서 검토’를 추가했다. 저장소 읽기 실패나 미지원 버전은 기존 복구본을 덮어쓰지 않는다.
- 복구 시 권한과 파일 변경을 확인하고 중복 검사 결과는 재사용하지 않는다. 복구 도중 오류가 나면 화면 상태를 되돌리고 저장된 복구본을 유지한다. 다른 탭에서 동시에 복구본을 덮어쓰지 않도록 Web Locks를 사용했다.
- 실행 완료된 파일은 복구본에서 제거하고, 보류·제외·부분 실행 실패 시 남은 파일의 수정값을 유지한다. 검사 후 파일 변경과 실행 직전 대상 파일 존재 여부도 확인한다.
- 중복 후보를 크기로 묶고 SHA-256 인덱스로 비교한다. 경로·크기·수정 시각이 유효한 해시는 입력 수정과 재검사에서 재사용한다. 캐시에는 해시만 보관하며 최대 4,096개로 제한했다.
- 파일 내용은 순차 처리하고 중간에 화면 갱신 시간을 둔다. 검사 진행률·취소 기능을 추가하고 검사 중 입력·실행을 잠근다. 취소·실패 후에는 검사를 다시 해야 실행할 수 있다.
- 기존 색상을 흰색·검정·중립 회색으로 바꿨다. 입력 16px, 주요 라벨·버튼 15px를 적용하고 오류·보류 상태는 문구와 테두리로 구분했다. 화면 밖 정리 카드에는 content-visibility를 적용했다.

## Decisions

- 첫 단계에는 기존 정리 화면과 물리적 저장 규칙을 유지했다. 최대 100개 묶음, 목록＋상세 편집, 특수 폴더 선택 제거, Pattern Library와 분류 기능은 다음 단계에서 구현한다.
- 검토 복구는 브라우저 IndexedDB를 사용한다. 실제 도안의 파일명과 내용을 변경하지 않으며, 기존 디자이너 연결 JSON 형식도 유지한다. 저장 완료 표시 전의 입력이나 브라우저 데이터 삭제는 복구를 보장하지 않는다.
- 중복 판정은 기존처럼 파일 바이트 완전 일치다. 크기가 다르면 해시를 계산하지 않고, 편집 변경으로 검사 결과만 무효화하고 유효한 해시는 유지한다.
- 초기 패턴 폴더 선택은 작업 교체로 보지 않는다. 이미 진행 중인 폴더를 교체하거나 이전 복구본으로 새 작업을 시작할 때만 확인한다.
- 실제 컬렉션의 안전을 위해 Playwright와 설치된 Chrome의 임시 프로필·OPFS 임시 폴더에서 검증했다. 당시 검증 지침이 기대하는 Browser 경로만 확인하고 연결 도구가 없다고 잘못 판단해 Playwright를 사용했다. 이후 도구 목록을 직접 조회해 인앱 브라우저와 Chrome 연결이 이미 있다는 것을 확인했다. 복구 오류에서 부분 화면 상태가 남는 경우를 발견해 롤백을 추가했고, 비동기 폴더 선택 검증은 완료 상태를 기다리도록 정리했다.

## Current Status

- 저장 실패·재시도와 실행 차단, 검사 취소, 완전 중복, 동명 다른 내용 보류, 제외, 실제 임시 파일 이동·삭제, 부분 실행 실패 시 남은 수정값, 검사 후 파일 변경 차단을 검증했다.
- 기존 별칭 JSON 불러오기·파일명 정규화와 Singles 3개 승격이 통과했다. 재검사에서 파일 내용 읽기 6회가 0회로 줄었다.
- 서로 다른 크기의 200·400개 임시 파일과 같은 크기의 약 64KB 파일 200·400개로 검사했다. 크기가 다른 묶음은 내용 읽기 0회, 같은 크기 묶음은 최초 파일 수만큼 읽고 재검사에서는 0회였다. 이 수치는 실제 대용량 도안 컬렉션의 성능을 의미하지 않는다.
- Chrome 100% 줌의 2048px·1280px CSS 폭에서 흑백 스타일, 16px 입력, 가로 넘침 없음과 편집·실행 버튼 접근을 확인했다. 예상한 오류 주입 외에 JavaScript 런타임 오류는 없었다.
- 실제 Windows 도안 폴더의 권한 프롬프트와 대용량 PDF 성능은 미검증이다. 라이브러리 JSON·외부 백업·실행 중 강제 종료의 자동 재개는 후속 단계 범위다. 로컬 변경만 완료했으며 배포·커밋·푸시는 하지 않았다.

- `!pdf-organizer-library.json` 버전 1에 도안 ID, 상대 경로, 크기·수정 시각, 분류 ID와 출처를 저장한다. 직전 정상 JSON은 별도 backup.json에 남기고 저장 전에 디스크 변경 여부를 비교한다.
- 파일명에서 영문·한글 단어 또는 구문이 완전히 일치할 때 자동 분류한다. 키워드 재분석은 자동 분류만 갱신한다. PDF 텍스트는 아직 읽지 않는다.
- 이동은 복사 → JSON 저장 → 원본 제거 순서로 변경했다. JSON 저장 실패 시 새 복사본을 정리하고 원본을 유지한다. JSON 저장 후 원본 제거가 실패하면 두 PDF와 대상 분류를 남긴다.
- Singles 승격 시 기존 도안 ID·수동 분류를 보존한다. 완전 중복본 삭제는 기존 도안 분류를 유지한다.
- 다른 저장 작업에서 저장 전 도안 분류·카테고리 편집값이 사라지지 않도록 보존하고 취소 기능을 추가했다. 미저장 편집 중에는 폴더 교체·목록 재연결·정리 작업을 막는다.
- 카테고리 관리를 긴 PDF 목록 위로 옮기고 저장·추가 도구를 상단에 배치했다. 글자를 줄이지 않고 선택 칩과 도구를 줄바꿈한다.
- 다운로드/패턴 폴더의 동일·상하위 경로 연결을 거부한다. 라이브러리 원본을 다운로드 중복본으로 취급하는 위험을 피하기 위한 제한이다.
- Node 회귀 테스트와 분리된 Chrome 통합 테스트, 분류·JSON 오류 주입용 OPFS 샘플 도구를 추가하고 README를 갱신했다.

## Decisions - 카테고리와 라이브러리 메타데이터

- 카테고리는 물리적 폴더와 독립적으로 저장한다. 분류 편집 자체는 PDF 이름·내용·위치를 변경하지 않는다.
- Other와 Unknown은 삭제하지 못하게 하고 자동 추론에서는 제외했다. Unknown은 다른 분류와 함께 저장하지 않는다. 수동 Unknown도 재분석으로 바꾸지 않는다.
- 불확실한 이름은 Unknown으로 두며, 완전 단어 일치 방식으로 `hat`이 `that`이나 `Hatfield`에 붙는 오분류를 막았다. 한 파일에 여러 명확한 종류가 나타나면 복수 분류한다.
- JSON의 도안 기록을 일괄 삭제하지 않는다. 외부 경로 변경·동일 경로의 파일 교체는 이전 기록을 보존하고 새 도안으로 색인한다. 근거 없이 수동 분류를 새 파일에 붙이지 않으며 선택적 복구는 후속 단계로 남겼다.
- 저장 실패에 대비해 원본 제거 전에 분류를 디스크에 확정한다. 실패 후 남은 두 복사본은 다음 중복 검사에서 처리할 수 있다.
- 복구 직후 새 분류 컨트롤이 비활성 상태로 남는 문제를 발견했다. 작업 잠금 전에 비활성 값을 미리 설정하지 않도록 수정하고 브라우저 회귀 검증에 포함했다.

## Current Status - 카테고리와 라이브러리 메타데이터

- Node 테스트 18개 통과: 이전 묶음 테스트 7개와 분류·JSON·이동·실패 보호 테스트 11개. 스크립트 문법, HTML 파일 연결, 중복 DOM ID, Git 공백 검사도 통과했다.
- 연결된 인앱 브라우저에서 복수 수동·일괄 분류, 추가·이름·순서·키워드 수정, 사용 중인 분류 삭제 후 재배정, 수동 분류 재분석 보호를 확인했다.
- 실제 OPFS 파일 처리에서 저장 실패 후 원본 200개 유지, 정상 이동 98개 / 중복 삭제 1개 / 보류 1개를 확인했다. 루트·특수 하위 폴더를 포함한 라이브러리 101개가 JSON에서 재연결됐다.
- 브라우저 검토 복구본을 비우고 JSON만 다시 읽어 같은 도안 ID와 복수 수동 분류가 유지됨을 확인했다. 손상/지원하지 않는 JSON은 덮어쓰지 않고 연결 오류를 표시했다.
- 별도 Chrome에서도 같은 전체 흐름과 미저장 분류 보존이 통과했다. 100% 줌의 2048px·1280px CSS 폭에서 가로 넘침 없음, 16px 입력·14px 분류 글자, 주요 버튼 접근을 확인하고 화면을 저장했다. 예상 오류 주입 1개 외 앱 오류·경고는 0개였다.
- Chrome 자동 테스트의 첫 실행은 샌드박스에서 로컬 네트워크 접근이 거부됐다. 동일한 임시 샘플 테스트를 승인된 실행 환경에서 다시 수행해 통과했다. 실제 도안 폴더에는 접근하지 않았다.
- 실제 Windows 도안 폴더와 대규모 컬렉션 성능은 미검증이다. 로컬 구현과 개발 로그 갱신까지 완료했으며 배포·커밋·푸시는 하지 않았다.
