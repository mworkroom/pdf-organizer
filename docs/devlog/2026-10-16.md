# 2026-10-16 PDF Organizer Development Log

## Work Summary

앱 UI 전체를 영어로 변경해 화면 설명, 파일 검토, 라이브러리 관리, 분석·복구 흐름에서 언어를 통일했다.

## Work Completed

- 초기 HTML과 동적으로 생성되는 버튼·라벨·도움말·빈 상태·진행 상태·오류·확인창·접근성 문구를 영어로 변경했다.
- 문서 언어를 `en`, 작업 로그 날짜 표시를 `en-GB`로 변경했다.
- PDF 미리보기의 변경 파일 오류 판별을 영어 오류 문구에 맞췄다.
- 개발 전용 QA 화면과 기존 테스트의 버튼 선택·문구 검증을 영어 UI에 맞게 변경했다.
- JavaScript 구문 검사와 Node 테스트 36개, Chrome 통합 테스트 3종(분류·정리, 갤러리, 분석·재연결)을 통과했다.
- Chrome 100% 줌의 2048×1152·1280×1152 화면에서 글자 크기와 주요 동작, 가로 넘침을 확인하고 스크린샷을 검토했다.
- 별도 초기 화면 점검에서 두 탭·별칭 펼치기·분석 및 카테고리 영역의 영어 본문과 접근성 속성을 확인했다.

## Decisions

- 사용자 파일명·디자이너명·사용자 정의 카테고리·기존 저장 기록을 번역하거나 마이그레이션하지 않는다. 언어 변경으로 원본 데이터나 안정적인 도안 ID가 바뀌지 않도록 했다.
- 한국어 파일명 및 PDF 분류에 필요한 한국어 키워드와 정규식은 유지했다. 이는 UI 번역 대상이 아닌 분류 데이터다.
- 기존 정렬·정규화 방식과 화면 배치는 유지했다. 영어 문구가 기존 레이아웃에서 줄바꿈되며 읽기 가능한 크기를 유지하는 것을 확인했다.

## Current Status

- 영어 UI 변경과 로컬 검증을 완료했다. 통합 테스트의 예상된 저장 실패 주입 외에 예기치 않은 브라우저 오류는 없었다.
- 처음 실행한 테스트의 일부가 기존 한국어 오류 문구를 기대해 실패했으며, 기대 문구를 영어로 갱신한 후 모두 통과했다.
- 샌드박스가 로컬 서버 접속을 차단해 허용된 확장 실행 권한으로 격리된 Chrome 테스트를 완료했다. 실제 도안 폴더 대신 임시 OPFS 샘플만 사용했다.
- 기존 저장 데이터의 한국어 문구 및 브라우저·운영체제가 제공하는 기본 대화상자의 언어는 유지될 수 있다. 배포·커밋·푸시는 수행하지 않았다.

## Next Steps

- 앱을 새로고침해 영어 UI를 사용할 수 있다. 실제 모니터에서 J님의 가독성 피드백이 있으면 문구 길이와 배치를 조정한다.

## Work Summary - 정리 화면과 라이브러리 일괄 분류 역할 분리

J님이 신규 파일을 차례로 검토할 때 좌우 선택·편집 반복이 느리다고 설명했고, 대량 분류는 이미 모아 둔 미분류 도안을 디자이너별로 정리할 때 필요하다고 제안했다. Organize Files는 세로 연속 편집으로 바꾸고 Pattern Library에 선택·일괄 분류를 추가했다.

## Work Completed - 정리 화면과 라이브러리 일괄 분류 역할 분리

- 정리 화면의 왼쪽 선택 목록과 신규 파일 일괄 도구를 제거했다. 현재 묶음의 최대 100개 파일을 편집 카드로 이어 보여 주며 파일별 입력·분류·제외를 즉시 수정한다.
- 입력 중에는 전체 카드를 다시 만들지 않고 필요한 분류·미리보기만 갱신한다. 화면 밖 카드에는 기존 `content-visibility`를 적용하고, 기존 v1/v2 자동 저장·복구 및 처리 경계를 유지했다.
- 라이브러리 검색·필터 아래에 선택 모드, 카드별 선택, 현재 페이지 선택, 검색 결과 전체 선택, 선택 개수와 대체 분류 도구를 추가했다.
- 페이지·정렬·보기 전환에서는 선택을 유지한다. 검색·분류·디자이너 조건 변경에서는 선택을 해제하고 검색 갱신 중에는 선택·적용을 잠근다. 폴더 식별자와 파일 경로·크기·수정 시각으로 오래된 선택이 재사용되지 않게 했다.
- 대상 개수·대체 분류를 확인한 뒤 메타데이터 JSON을 한 번 저장한다. 선택한 도안의 분류만 교체하며 수동 분류로 남겨 재분석으로 바뀌지 않게 했다. 저장 실패 시 선택과 대체 분류를 유지한다.
- 개별 분류·대표 페이지·카테고리 편집이 저장되지 않았으면 일괄 적용을 막아 기존 편집을 보호한다.
- HTML의 앱 스크립트와 CSS에 공통 릴리스 쿼리를 붙여 배포 시 이전 JavaScript 캐시와 새 HTML이 섞이는 문제를 줄였다. 누락 항목 강조용 CSS 문구도 영어로 수정했다.
- README와 기존 Chrome 회귀 검증을 새 화면에 맞게 갱신하고, 일괄 분류 모델 테스트와 전체 작업 흐름 Chrome 테스트를 추가했다.

## Decisions - 정리 화면과 라이브러리 일괄 분류 역할 분리

- 신규 파일 검토의 100개 처리 경계와 라이브러리의 24개 표시 단위는 독립적으로 유지한다. 라이브러리 분류는 검색 결과 전체를 선택할 수 있다.
- 디자이너 전문 분야로 자동 분류하지 않는다. J님이 필터와 선택으로 대상을 정하고 분류를 직접 적용한다.
- 일괄 분류는 기존 분류를 교체하는 동작으로 명확히 표시한다. 도안 ID·경로·대표 페이지·분석 기록과 PDF 파일은 변경하지 않는다.
- 분류 도구는 대체 분류가 처음부터 선택되지 않은 상태로 시작해 의도하지 않은 Unknown 적용을 방지한다.
- 기존 복구본의 선택 필드는 호환성을 위해 읽되, 신규 화면의 파일 선택 목록으로 사용하지 않는다. 라이브러리 선택·적용 전 분류는 새로고침 시 복구하지 않으며 README에 기록했다.
