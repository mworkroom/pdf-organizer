# 2026-10-15 PDF Organizer Development Log

## Work Summary

계획서 4단계인 전체 PDF 갤러리·썸네일·검색·필터·대표 페이지 선택을 구현했다. 3단계의 분류 JSON과 파일 이동 보호를 유지하면서, 라이브러리 탐색에서 모든 PDF 내용을 한꺼번에 읽지 않도록 구성했다. 흑백 UI와 읽기 쉬운 글자 크기를 유지했다.

## Work Completed

- 루트·Singles·특수 폴더와 모든 하위 폴더의 기존 색인을 갤러리로 연결했다. 전체 컬렉션 검색과 별개로 DOM에는 최대 24개 카드만 표시한다.
- 파일명·상대 경로·디자이너·카테고리 이름 검색, 카테고리/디자이너 조건 교집합, 파일 이름·디자이너·수정 시각 정렬, 갤러리/목록 전환을 추가했다. 복수 분류는 어느 분류로도 검색한다.
- 공식 npm의 PDF.js 6.4.299 패키지를 SHA-512 무결성 검사 후 앱에 포함했다. 모듈·워커·폰트·CMap·WASM 및 라이선스는 vendor/pdfjs에 있고 배포 정보와 재현 스크립트를 남겼다.
- 화면과 약 100px 주변의 카드부터 PDF를 한 파일씩 읽고 대표 페이지를 렌더링한다. 처음에는 1페이지이며, 필터·페이지·탭 전환에서 이전 요청을 취소한다. 완료 후 PDF 문서와 캔버스를 해제하고 이전 blob URL도 폐기한다.
- 별도 IndexedDB 썸네일 캐시를 최대 200개 / 40MiB로 제한했다. 도안 ID·라이브러리 ID·크기·수정 시각·페이지·렌더러 버전으로 구분하며 캐시 실패가 현재 이미지 표시를 막지 않는다.
- PDF의 실제 페이지 범위를 확인한 뒤 대표 페이지를 JSON에 저장한다. 저장 전 페이지 입력도 분류와 함께 필터·화면 전환에서 보존하고, 저장·취소 전에는 폴더 재연결과 정리 작업을 막는다.
- 손상·암호 필요·파일 읽기 실패는 해당 카드에 원본 열기/재시도 경로를 제공한다. 미리보기 오류가 도안 기록을 삭제하거나 다른 PDF를 막지 않는다.
- 새로 정리되는 Singles의 디자이너 표기를 메타데이터에 보존했다. 기존 Singles는 파일 접두어를 사용하며, 루트·특수 폴더에서 디자이너를 임의 추정하지 않는다.
- Chrome 검색창의 기본 취소 아이콘도 회색으로 표시해 흑백 색상 체계를 유지했다.
- 로컬 서버의 모듈·폰트·WASM MIME 형식을 추가하고 README와 회귀 테스트, 131개 갤러리 QA 샘플을 갱신했다. QA 정리는 알려진 OPFS 샘플과 해당 라이브러리의 캐시에만 적용한다.

## Decisions

- PDF.js를 동일 출처의 정적 파일로 제공한다. CDN 런타임 요청과 PDF 업로드 없이 브라우저에서 렌더링하며, 일반 탐색에서는 PDF 해시를 계산하지 않는다.
- 다운로드 정리의 100개 묶음과 라이브러리 표시의 24개 페이지는 서로 독립적이다. 검색은 현재 페이지에 제한하지 않는다.
- 썸네일을 JSON에 넣지 않는다. 캐시는 지울 수 있는 임시 자료이고, 분류와 대표 페이지는 패턴 폴더 JSON에 남는다.
- 필터·페이지를 바꾸더라도 저장 전 페이지 숫자가 초기화되지 않게 별도 편집 상태를 보존했다. 범위를 벗어나거나 JSON 저장이 실패하면 기존 대표 페이지는 유지한다.
- 정렬 비교기를 매번 만들지 않도록 Intl.Collator를 재사용하고, 같은 메타데이터/검색 조건의 결과를 화면 렌더링과 버튼 계산에서 공유한다.
- 테스트 화면을 처음에는 일부 썸네일 준비 중에 캡처했다. 최종 증거는 화면 주변 카드의 처리가 끝난 뒤 촬영하도록 대기 조건을 수정했다.

## Work Completed - 5단계 PDF 텍스트 분석과 외부 이동 복구

- 라이브러리에 들어온 PDF만 첫 3페이지까지 한 파일씩 분석한다. 미리보기와 동일한 직렬 PDF 작업 슬롯을 사용하고, 종료 시 문서를 해제한다.
- 제목 크기의 짧은 문구·명시적 종류 표기로만 분류한다. 재료·바늘·설명 문장은 제외하고, 파일명 분류와 충돌하면 기존 분류와 제안을 함께 남긴다. 수동 Unknown·복수 분류는 유지한다.
- PDF별 분석 상태·페이지 수·분류 ID·SHA-256을 JSON에 저장한다. 일시정지, 폴더 재연결 후 남은 작업 재개, 실패 PDF 재시도를 제공한다. JSON 저장 실패 시 해당 파일은 미분석 상태로 남긴다.
- 실제 정리 이동 시 원본 제거 전에 해시를 저장한다. 중복 검사에서 구한 값은 재사용한다. PDF 본문 전체는 메타데이터에 넣지 않는다.
- 누락된 도안과 같은 크기의 후보를 선택하고, 원본 열기·선택 후보 해시 확인·확인란·연결 저장 순서로 복구한다. 해시 불일치와 후보의 수동 분류는 연결을 막는다. 저장 직전 파일 상태와 해시를 다시 확인한다.
- 연결한 도안의 ID·분류·대표 페이지를 유지하고, 대체된 후보 기록도 JSON에 보존한다. 재색인 시 대체 기록이 기존 ID를 가로채지 않도록 했다. 원래 경로로 돌아온 변경 없는 누락 파일도 ID를 복원한다.
- UI는 14~16px 컨트롤과 경로 줄바꿈을 사용한다. 문서·검증용 샘플·회귀 테스트를 갱신했다.

## Decisions - 5단계 PDF 텍스트 분석과 외부 이동 복구

- 분석은 정리 성공 후 별도로 시작한다. 본문 추론 실패가 이미 완료된 물리적 정리를 실패로 보이게 하지 않으며, 큰 라이브러리도 원하는 때 중단·재개할 수 있다.
- 스캔 PDF는 OCR을 도입하지 않고 수동 분류로 남긴다. 불확실한 제목이나 본문 충돌은 기존 분류를 덮어쓸 근거로 사용하지 않는다.
- 이전 해시가 없는 메타데이터는 동일 파일임을 자동 증명할 수 없다. 직접 확인했다는 선택을 받아 연결하고, 저장된 해시와 다르면 수동 확인으로도 우회하지 못하게 했다. 같은 복사본 여러 개도 자동 연결하지 않는다.
- 크기가 달라진 후보와 이미 수동 분류된 후보는 이 복구 단계에서 자동 통합하지 않는다. PDF 파일 작업 없이 JSON 연결만 변경하므로 잘못 연결된 경우에도 원본은 남는다.
- 최초 통합 검증에서 QA 보고서의 500ms 갱신 지연 때문에 해시 읽기 횟수 대기가 실패했다. 화면의 확인 완료와 보고서 동기화를 구분해 검증 조건을 수정했다. 기능의 해시 결과는 일치했다.
