# PDF Organizer

Chrome에서 로컬 뜨개 도안 PDF를 최대 100개씩 정리하는 정적 웹 앱입니다. PDF와 검토 내용은 서버로 업로드하지 않습니다.

## 로컬 실행

Node.js가 설치된 환경에서 다음 명령을 실행하고 표시된 주소를 Chrome이나 인앱 브라우저에서 엽니다.

```sh
node scripts/dev-server.cjs
```

기본 주소는 `http://127.0.0.1:8766`입니다. 배포에는 빌드가 필요 없으며 `index.html`, `css/`, `js/`를 함께 제공합니다.

HTML의 앱 스크립트·스타일 URL은 같은 릴리스 쿼리 버전을 사용합니다. UI 구조가 바뀌는 배포에서는 이 버전을 함께 갱신해 이전 캐시의 스크립트가 새 HTML과 섞이지 않게 합니다.

## 작업 흐름

1. 패턴 폴더와 다운로드 폴더를 연결합니다. 첫 작업 묶음에는 파일명 순서로 최대 100개가 들어갑니다.
2. Organize Files에서 파일별 편집 카드를 위에서 아래로 스크롤하며 디자이너·원본 디자이너 표기·저장 파일명·분류를 바로 수정합니다. 파일 선택을 위한 별도 목록은 없으며 개별 제외·해제와 자동 저장을 지원합니다.
3. 중복 검사 후 현재 묶음을 정리합니다. 다음 파일들은 다운로드 폴더에 남아 있으며 ‘다음 100개 검토’로 불러옵니다.
4. 보류·제외 파일은 별도 목록으로 남습니다. 전체 묶음을 미루려면 ‘현재 묶음 보류’를 사용합니다. ‘보류·제외 다시 검토’는 현재 묶음이 비어 있을 때 최대 100개씩 엽니다.

검토 내용, 현재 묶음·대기·보류 구분과 선택 파일은 IndexedDB에 자동 저장됩니다. 저장 완료된 내용은 ‘이어서 검토’로 복구하며, 중복 검사는 다시 수행합니다. 브라우저 데이터를 삭제하면 복구할 수 없습니다. 이전 v1 복구본도 읽으며, 100개를 넘는 파일의 수정 내용은 대기 목록으로 보존합니다.

새 정리 작업의 저장 위치는 디자이너 폴더 또는 `!zz_Singles`입니다. 기존 특수 폴더 파일은 앱에서 자동 통합하지 않습니다. Pattern Library 탭에서 전체 PDF 갤러리·검색·카테고리·대표 페이지를 관리하고, 정리 후 텍스트 분석과 외부 이동 연결 복구를 실행할 수 있습니다.

## 기존 도안 일괄 분류

Pattern Library에서 카테고리 `Unknown`과 디자이너를 함께 필터링하고 `Select patterns`를 누릅니다. 카드별 선택, 현재 페이지 전체 선택, 검색 결과 전체 선택을 지원합니다. 선택은 페이지·정렬·갤러리/목록 전환에서 유지되며 검색·카테고리·디자이너 조건 변경과 패턴 폴더 교체에서는 해제됩니다.

대체할 카테고리를 하나 이상 선택하고 `Apply categories`를 누르면 대상 개수와 분류를 확인한 뒤 기존 분류를 교체합니다. 수동 분류로 저장하므로 자동 재분석에서도 유지됩니다. 도안 ID·경로·대표 페이지와 PDF 파일은 변경하지 않습니다. 저장 실패 시 선택과 대체 분류를 유지해 다시 시도할 수 있습니다. 개별 분류·대표 페이지·카테고리 이름의 미저장 편집은 먼저 저장하거나 취소해야 합니다. 선택 상태와 적용 전 대체 분류는 페이지 새로고침 후에는 유지되지 않습니다.

신규 파일의 100개 처리 제한과 라이브러리 24개 표시 단위는 별개입니다. 일괄 분류는 현재 검색 결과 전체를 대상으로 할 수 있으며 분류 JSON을 한 번 저장합니다.

## 파일 구성

- `css/style.css`: 흑백 스타일과 반응형 목록·상세 편집
- `js/app.js`: 공유 상태와 앱 이벤트 초기화
- `js/catalog-model.js`, `js/catalog.js`: 카테고리·복수 분류·버전 1 메타데이터 JSON과 전체 PDF 색인
- `js/gallery-model.js`, `js/gallery.js`: 전체 컬렉션 검색·필터·정렬, 24개씩 갤러리/목록, 대표 페이지 편집
- `js/library-bulk.js`: 기존 도안의 페이지 간 선택과 카테고리 일괄 교체
- `js/pdf-preview.js`, `js/thumbnail-store.js`: 한 파일씩 PDF 렌더링과 제한된 IndexedDB 썸네일 캐시
- `js/maintenance-model.js`, `js/maintenance.js`: 정리 후 PDF 텍스트 분석·일시정지/재개·선택한 외부 이동 후보 연결
- `vendor/pdfjs/`: 앱에서 제공하는 PDF.js 6.4.299 모듈·워커·폰트·CMap·WASM과 라이선스
- `js/organizer.js`: 중복 검사·이동 계획·파일 처리
- `js/batch.js`, `js/review.js`: 100개 묶음·대기·보류 관리와 검토 화면
- `js/storage.js`, `js/draft-store.js`: 복구 흐름과 IndexedDB
- `js/aliases.js`, `js/logs.js`, `js/utils.js`, `js/library.js`: 별칭·로그·공통 함수·탐색 화면

기존 처리 로직을 보존하기 위해 프레임워크 없이 역할별 스크립트를 분리했습니다. 스크립트는 `index.html`의 `defer` 순서로 로드하며, 공유 상태는 함수 정의 파일을 로드한 뒤 `app.js`에서 초기화합니다.

## 검증

```sh
node --test tests/*.test.cjs
```

브라우저 통합 검증은 실제 도안 폴더 대신 OPFS 임시 샘플을 사용합니다. PowerShell에서 아래와 같이 서버를 시작한 후 `http://127.0.0.1:8766/?qa=1`을 엽니다.

```powershell
$env:PDF_ORGANIZER_QA = '1'
node scripts/dev-server.cjs
```

QA 도구는 샘플 파일 생성, 구버전 복구본, 저장·이동·폴더 읽기 오류 주입을 제공합니다. 해당 샘플에 한해 확인창을 자동 승인하며, 실제 선택 폴더에는 적용하지 않습니다. 테스트 후 ‘샘플 작업 종료’로 샘플과 복구본을 정리합니다. 이 도구는 QA 옵션을 켠 로컬 서버에서만 주입되며 일반 실행·정적 배포에는 나타나지 않습니다.

## 분류 저장

패턴 폴더의 `!pdf-organizer-library.json`에 안정적인 도안 ID, 상대 경로, 파일 크기·수정 시각, 카테고리 ID와 수동/파일명 분류 출처를 저장합니다. 직전 정상본은 `!pdf-organizer-library.backup.json`에 남습니다. 브라우저 데이터를 삭제해도 같은 폴더를 다시 연결하면 분류를 읽습니다. 검토 중인 다운로드 파일은 기존 IndexedDB 복구본에 저장하고, 실제 이동 시 JSON으로 옮깁니다.

기본 23개 카테고리는 이름·순서·쉼표로 구분한 추론 키워드를 편집할 수 있습니다. Other와 Unknown은 의미를 보존하기 위해 삭제할 수 없으며 자동 추론 대상으로 사용하지 않습니다. Unknown은 다른 카테고리와 함께 선택할 수 없습니다. 사용 중인 카테고리를 삭제할 때는 대체 분류를 선택해야 하며 복수 분류의 나머지 항목은 유지합니다.

파일명에서 완전한 단어/구문이 일치하는 경우만 자동 분류합니다. 수동 분류는 재분석으로 바꾸지 않습니다. 정리 이동은 PDF 복사 → JSON 저장 → 원본 제거 순서입니다. JSON 저장 실패 시 복사본을 정리하고 원본은 남깁니다. JSON 저장 후 원본 제거가 실패하면 양쪽 PDF와 저장된 분류를 남겨 다음 중복 검사로 처리할 수 있습니다. 완전 중복 다운로드본을 삭제할 때는 기존 도안의 분류를 유지합니다.

다운로드 폴더와 패턴 폴더는 같은 위치이거나 서로의 하위 폴더일 수 없습니다. 라이브러리 파일을 다운로드 중복본으로 취급하지 않도록 연결·복구·실행 전에 확인합니다. 기존 도안의 저장 전 분류와 카테고리 편집은 다른 저장 작업에서 유지하고, 편집 중에는 목록 새로고침·폴더 교체를 막습니다.

선택적 Chrome 통합 테스트는 `node tests/catalog.browser.cjs`로 실행합니다. 로컬 QA 서버와 `playwright` 모듈, Chrome이 필요하며, 별도 Chrome 컨텍스트의 OPFS 샘플만 사용합니다. `PDF_ORGANIZER_ARTIFACT_DIR`를 지정하면 화면 증거를 그 경로에 저장합니다.

전체 하위 폴더와 루트 PDF를 색인하지만 일반 목록 탐색에서는 해시를 읽지 않습니다. 외부에서 경로·파일 정보가 바뀌면 이전 메타데이터를 보존하고 새 도안으로 표시하며, 자동으로 수동 분류를 다른 파일에 붙이지 않습니다. 손상된 JSON 또는 지원하지 않는 버전은 덮어쓰지 않으며 오류를 표시하고 정리를 막습니다. 원본 JSON과 백업을 별도 보관한 후 정상본을 복원하고 목록을 새로고침하세요.

## 갤러리와 미리보기

검색은 현재 페이지와 관계없이 전체 PDF의 파일명·상대 경로·디자이너·저장된 카테고리 이름을 대상으로 합니다. 여러 검색 단어는 모두 일치해야 하며, 카테고리와 디자이너 필터는 검색 조건과 함께 적용합니다. 복수 분류 도안은 어느 분류로도 찾을 수 있습니다. 디자이너 폴더는 첫 경로를 기준으로 표시하고, Singles는 저장된 디자이너명 또는 기존 파일의 첫 밑줄 앞 표기를 사용합니다. 루트·특수 폴더에서 디자이너를 임의로 추측하지 않습니다.

한 페이지에 최대 24개 카드를 만들고 갤러리·목록 전환, 파일 이름·디자이너·파일 수정 시각 정렬을 제공합니다. 표시 방식만 브라우저 설정으로 유지하며 검색 조건은 JSON에 쓰지 않습니다. 라이브러리 탐색은 다운로드 정리의 100개 묶음 제한과 별개입니다.

썸네일은 화면과 약 100px 주변에 보이는 카드부터 생성합니다. 기본값은 첫 페이지이며 모든 요청을 한 PDF씩 직렬 처리하고, 페이지 전환·필터 변경·탭 이탈 시 이전 요청을 취소합니다. PDF 문서와 캔버스는 렌더링 후 해제하고, 카드의 blob URL은 재표시 때 폐기합니다. 손상·암호 필요·읽기 실패 시 해당 카드에 원본 열기와 재시도 경로를 남기며 도안 메타데이터를 삭제하지 않습니다.

썸네일 캐시는 별도 IndexedDB에 최대 200개 / 40MiB로 제한합니다. 키는 라이브러리 ID·도안 ID·크기·수정 시각·대표 페이지·렌더러 버전을 포함합니다. 캐시 오류가 나도 현재 미리보기는 표시하고 다음 방문에 다시 생성할 수 있습니다. ‘썸네일 캐시 비우기’는 분류 JSON과 원본 PDF를 변경하지 않습니다.

대표 페이지는 PDF의 실제 페이지 범위로 검증한 뒤 JSON에 저장합니다. 범위를 벗어나거나 저장이 실패하면 이전 대표 페이지와 입력값을 유지합니다. 저장 전 분류·페이지 입력은 필터·표시 방식 변경에서도 유지하고, 취소로 되돌릴 수 있습니다.

## 정리 후 텍스트 분석과 외부 이동 복구

Pattern Library → **PDF 텍스트 분석 · 외부 이동 복구**에서 실행합니다. 다운로드 검토 중에는 PDF 텍스트를 읽지 않으며, 물리적 정리가 끝난 뒤 원하는 때 분석할 수 있습니다. 미분석 PDF 분석은 라이브러리의 첫 3페이지까지 읽고, 기존 미리보기와 같은 직렬 처리 슬롯을 사용합니다. 제목 크기의 짧은 문구, 단독 종류명 또는 명시적인 종류 표기에서만 분류를 추론합니다. 바늘·재료·설명 문장에 등장하는 단어는 근거로 삼지 않습니다. 파일명 분류와 충돌하면 기존 분류를 유지하고 상세 카드에 제안을 표시합니다. 수동 Unknown을 포함한 모든 수동 분류는 유지합니다.

한 PDF의 결과마다 JSON에 분석 상태·확인 페이지 수·분류 근거 ID와 SHA-256을 저장합니다. PDF 본문 전체와 이미지는 JSON에 저장하지 않습니다. 일시정지나 탭 종료 후 폴더를 다시 연결하고 ‘미분석 PDF 분석 · 이어서’를 누르면 저장이 끝난 파일은 건너뜁니다. JSON 저장 실패 시 그 파일부터 미분석 상태로 남아 재개할 수 있습니다. 손상·암호 필요·읽기 실패는 개별 오류로 기록하며 ‘실패한 PDF 다시 분석’으로 다시 시도합니다. 텍스트 없는 PDF에는 OCR을 적용하지 않습니다. 텍스트 추출은 [PDF.js getTextContent API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html#getTextContent)를 사용합니다.

실제 정리 이동 때에도 원본 제거 전에 SHA-256을 JSON에 저장하며 중복 검사에서 이미 계산한 값은 재사용합니다. 기존 라이브러리도 텍스트 분석을 실행하면 이후 외부 이동 복구에 쓸 해시를 갖게 됩니다. 이는 일반 갤러리 탐색과 별개이며 전체 컬렉션 해시 검사를 자동 실행하지 않습니다.

외부에서 이동하거나 이름을 바꾼 뒤에는 ‘패턴 목록 새로고침’을 누릅니다. 이전 도안과 같은 크기의 현재 파일 후보 중 하나를 선택하고 ‘후보 PDF 열기’로 내용을 확인할 수 있습니다. ‘선택 후보 해시 확인’은 해당 파일만 읽습니다. 이전 SHA-256과 다르면 연결을 막으며, 같은 복사본이 여러 개라도 자동 선택하지 않습니다. 확인란을 선택하고 연결을 저장하면 이전 도안 ID·수동 분류·대표 페이지를 유지합니다. 저장 직전 파일을 다시 확인하고 해시를 재계산합니다. 후보에 별도의 수동 분류가 있으면 덮어쓰지 않고 연결을 막습니다.

이전 해시가 없는 오래된 도안은 같은 크기만으로 동일 파일임을 증명할 수 없습니다. 이 경우 ‘이전 해시 없음’을 표시하고 직접 내용을 확인했다는 명시적 선택을 받아 연결합니다. 크기까지 달라진 파일은 이 복구 대상으로 제안하지 않습니다. 복구는 JSON 연결만 바꾸며 PDF를 이동·삭제하지 않습니다. 대체된 후보 기록도 JSON에 남기되 추가 누락 파일로 다시 제안하지 않습니다. 새 연결은 재색인에서도 유지됩니다.

`node tests/maintenance.browser.cjs`는 Chrome의 별도 OPFS 샘플로 첫 3페이지 제한, 수동 분류 보호, 일시정지·새로 연결 후 재개, 저장 실패, 해시 불일치, 중복 후보, 이전 해시 없는 연결과 2048/1280px 화면을 검증합니다.

PDF.js는 [공식 API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html)와 [렌더링 예제](https://mozilla.github.io/pdf.js/examples/)를 기준으로 연결했습니다. 공식 npm 배포 패키지를 SHA-512 무결성 검사 후 `vendor/pdfjs/`에 포함했으며 CDN 런타임 요청과 PDF 업로드는 없습니다. 버전·배포 주소·무결성 값은 `vendor/pdfjs/distribution.json`, Apache 2.0과 폰트 관련 라이선스는 해당 vendor 디렉터리에 있습니다. 갱신할 때는 `scripts/vendor-pdfjs.py`의 고정 버전과 렌더러/캐시 버전을 함께 변경하세요.

갤러리 통합 테스트는 QA 서버에서 `node tests/gallery.browser.cjs`로 실행합니다. 131개 OPFS 샘플, 전체 검색·복수 분류, 페이지 선택/복원, 미저장 편집 보호, 손상 PDF, 직렬 처리, 캐시 한도와 2048px·1280px 화면을 확인합니다. 배포 시 HTML, css, js와 `vendor/pdfjs/` 정적 파일을 함께 올려야 합니다.
